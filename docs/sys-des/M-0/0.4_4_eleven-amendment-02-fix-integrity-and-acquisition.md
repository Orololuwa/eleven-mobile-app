# Eleven — Amendment 02: Fix Integrity & Acquisition

**Status:** Draft v1 (B0 only shipped)
**Milestone:** M0
**Amends:** 0.4, 0.4.3, 0.5 (§3.9 live signal)
**Trigger:** Field session, 16 Oct 2026 — Eleven lost its GPS registration mid-run while Nike Run Club kept receiving 1 Hz fixes on the same phone
**Evidence:** [location-registration-dropout bug report](../../debug/2026-10-16_location-registration-dropout.md), `adb shell dumpsys location`

---

## B0 — Survive registration dropout (ship first)

None of the later integrity / acquisition work matters while the app is not subscribed to location. B0 is therefore ahead of everything else in this amendment.

### Problem

On 16 Oct, Eleven's GPS registration held for ~9 minutes, then dropped. After a brief churn of sub-two-second re-registrations, Eleven was **absent for the final ~35 minutes**. Nike's registration was continuous; the chip delivered clean 1 Hz fixes the whole time. The HUD showed *"Poor signal — move into open sky"* — wrong diagnosis: there were no fixes because the app was unsubscribed.

Root causes in code:

1. `processFix` called `stopLocationTracking()` on a single null / ended session lookup — a transient DB miss can unsubscribe mid-run.
2. Start and stop locks were independent — a stop can land between a start acquiring its lock and completing.
3. Nothing watched "session live" against "registration exists / fix arrived recently".
4. Live `poor` conflated "fixes arriving, quality too low" with "no fixes arriving".

### Changes

| Item | Behaviour |
|---|---|
| **Teardown policy** | Stop only on explicit `ended` / `ended_at`, or after **3** consecutive null session reads. A single null skips the fix and does not unsubscribe. |
| **Start/stop serialization** | Stop awaits the start lock; start awaits any in-flight stop. |
| **Watchdog** | While a session is live, every **10 s** assert that the location task is running and a fix arrived within **15 s**. Re-register on failure. Also re-check on app foreground. |
| **Live signal `offline`** | Fix feed stale or missing (after cold-start settle) → `offline`: *"Lost GPS connection — reconnecting."* / `NOT A SIGNAL PROBLEM · WAITING FOR FIXES`. `poor` keeps its meaning: fixes arriving, quality/bridge failing. |
| **Registration logs** | Every start / stop / re-register logs a reason (`start`, `stop`, `watchdog`, `foreground`, `ended`, `null-session-confirmed`). |

Constants: `LOCATION_WATCHDOG_INTERVAL_MS = 10_000`, `LOCATION_FIX_STALE_MS = 15_000`, `LOCATION_NULL_SESSION_STOP_AFTER = 3`.

### Out of scope for B0 (later sections)

Durable dedupe, provider discrimination, cold-start acquisition, Kalman smoothing, and sensor fallback remain valid follow-ons. They are not specified here yet.
